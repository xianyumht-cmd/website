### BUG-001：自动主题在白天调用 `classList.contains("")` 并抛出异常

- 严重级别：**P0**
- 状态：未修复
- 文件：`src/assets/js/theme-mode.min.js`
- 触发条件：本地时间处于 06:00—17:59，主题模式为 `auto`

问题代码把浅色状态转换为空字符串后传入：

```js
document.body.classList.contains(newAutoState === "dark" ? "night" : "")
```

当 `newAutoState === "light"` 时，实际执行 `classList.contains("")`。浏览器的 `DOMTokenList` 不允许空 token，会抛出异常，导致主题初始化或后续每分钟自动检查中断。

影响：

- 白天首次加载可能出现全局脚本错误提示；
- 自动主题状态无法稳定刷新；
- Playwright 的“控制台零报错”测试在白天应当失败；
- 后续同一事件链中的逻辑可能不再执行。

建议修复：

```js
const darkApplied = document.body.classList.contains("night");
const shouldBeDark = newAutoState === "dark";
if (this.autoState !== newAutoState || darkApplied !== shouldBeDark) {
  // ...
}
```

验收标准：白天、夜间、手动切换回自动模式三种场景均无 `DOMTokenList` 异常。

### BUG-002：损坏的语言 Cookie 会让导航数据初始化直接崩溃

- 严重级别：**P1**
- 状态：未修复
- 文件：`src/assets/app/resource-data.js`

`getCookie()` 对 Cookie 内容直接执行 `decodeURIComponent()`，没有捕获 `URIError`：

```js
return value ? decodeURIComponent(value.slice(prefix.length)) : null;
```

只要浏览器中存在不完整百分号编码，例如：

```text
language=%
```

导航数据初始化就会被异常打断，`window.navData` 不会建立，页面最终停留在加载占位或空白状态。

建议修复：对解码增加 `try/catch`，失败时删除无效 Cookie 并回退到 `zh`。

验收标准：手工设置 `language=%`、`site_language=%E0%A4%A` 后刷新，导航仍能正常显示中文。

### BUG-003：Playwright 启动命令写死 Windows `.cmd` 路径

- 严重级别：**P1**
- 状态：未修复
- 文件：`playwright.config.ts`

当前命令：

```text
npm run build && node_modules\.bin\vite.cmd preview ...
```

该路径只适用于 Windows。在 Linux、macOS 和常见 GitHub Actions Linux Runner 上无法运行，导致 E2E 测试在启动 Web Server 前失败。

建议修复：统一使用跨平台 npm 命令：

```text
npm run build && npm run preview -- --host 127.0.0.1 --port 4173
```

验收标准：Windows 与 Ubuntu Runner 都能启动 Playwright 测试。

### BUG-004：性能测试默认只能发现 Windows Chrome/Edge

- 严重级别：**P1**
- 状态：未修复

- 补充 Linux/macOS 常见路径；
- 或由 CI 明确注入 `CHROME_PATH`，并在工作流中验证文件存在。

### BUG-016：动态卡片和侧栏使用 `innerHTML` 拼接数据，缺少协议与内容校验

## 4. 待实机确认风险

### RISK-001：构建后移动 HTML，可能造成全部相对资源路径多退一级

- 风险级别：**接近 P0**
- 文件：
  - `vite.config.js`
  - `scripts/organize-dist.mjs`

Vite 使用：

```js
base: './'
```

多页面入口最初输出到 `dist/src/pages/<page>/index.html`，随后脚本把目录移动到 `dist/down/<page>/`，但没有重写 HTML 中由 Vite按原目录深度生成的相对资源路径。

示例风险：原路径可能是 `../../../assets/...`，移动后正确深度应为 `../../assets/...`。如果构建结果确实如此，`/down/nav/`、`/down/tdr/`、`/down/games/` 会出现 JS/CSS 404。

必须执行：

1. `npm ci`
2. `npm run build`
3. 检查 `dist/down/*/index.html` 的 `script`、`link` 路径
4. 用静态服务器打开并记录所有 404

在验证完成前，不应把当前构建链视为安全。

### RISK-006：`upgrade-insecure-requests` 与 HTTP 下载链接组合行为未验证

导航页声明 CSP `upgrade-insecure-requests`，数据中又存在 HTTP 链接。不同浏览器对导航、子资源和重定向的处理需要实机确认，尤其是旧安卓 WebView、微信/QQ 内置浏览器。

## 5. 质量门禁缺口

### QA-001：当前基线提交没有 GitHub Actions 验证记录

最新提交包含 HE 热修复，但没有对应工作流运行记录。代码是否构建、测试通过没有自动证据。

### QA-002：`npm test` 不包含视觉回归测试

`test:visual` 独立存在，但主 `test` 脚本没有调用。布局破坏不会自动阻止合并。

### QA-003：视觉快照以 Windows 平台命名

当前快照主要为 `*-win32.png`。Linux CI 上可能无法直接复用，且主测试未覆盖视觉快照。

### QA-004：缺少主题状态单元测试

没有覆盖：

- 白天自动模式；
- 夜间自动模式；
- 无效主题 Cookie；
- 自动模式跨 06:00/18:00 切换。

因此 BUG-001 和 BUG-013 没有在提交前被发现。

### QA-005：缺少数据 schema 与链接校验

应在构建前强制验证：

- 语言键只能是 `zh`、`en`；
- 主题值只能是 `auto`、`light`、`dark`；
- section ID 唯一；
- URL 只能是允许协议；
- 不允许 `#占位符` 伪装为下载入口；
- 不允许陈旧版本日期；
- 中英文项目数量和 URL 对齐。
