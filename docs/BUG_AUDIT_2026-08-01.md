# Website Bug 审查清单（通俗版）

- 审查日期：2026-08-01

## 先说明白

这里写的“Bug”不等于网站现在一定完全不能用。

它表示代码中已经发现了容易出错、影响使用或以后可能出问题的地方。严重程度分为：

- **P0：很严重**，可能让页面直接报错或打不开。
- **P1：重要**，会影响主要功能、发布或测试。
- **P2：一般**，某个功能不好用，或者部分用户会受影响。
- **P3：较轻**，主要是速度、显示或后期维护问题。

## 其他已发现问题

### BUG-001：白天自动主题可能报错

- 级别：P0
- 状态：未修复

通俗解释：网站设置为“自动主题”时，白天切换浅色模式的代码写错了，有可能弹出页面错误提示，或者主题切换失效。

用户可能看到：页面提示发生错误、主题按钮不正常，或者白天自动模式没有正确生效。

### BUG-002：异常语言记录可能让导航一直加载

- 级别：P1
- 状态：未修复

通俗解释：浏览器会记住用户选择的语言。如果这条记录损坏，网站没有自动恢复，导航内容可能加载不出来。

用户可能看到：页面一直显示“资源内容加载中”，但资源卡片始终不出现。

### BUG-003：网页自动测试只能在 Windows 正常启动

- 级别：P1
- 状态：未修复

通俗解释：测试命令里写死了 Windows 专用路径。在 Linux 服务器或 GitHub 自动检查环境中，测试会直接启动失败。

这不会直接影响普通访客，但会导致代码更新后无法可靠地自动检查网站是否被改坏。

### BUG-004：性能测试只会自动寻找 Windows 浏览器

- 级别：P1
- 状态：未修复

通俗解释：性能测试只认识 Windows 上的 Chrome 和 Edge。换到 Linux 或 macOS 后，测试会提示找不到浏览器。

结果是：项目虽然写了性能测试，但很多服务器环境实际上跑不起来。

### BUG-006：页面不允许复制密码和提取码

- 级别：P1
- 状态：未修复

通俗解释：导航里有很多“密码：123”“提取码：DC66”，但网站禁止选择和复制文字。

用户只能手动记住再输入，容易输错，也不方便手机用户。

### BUG-007：`spirit` 项目看起来能点，实际没有下载地址

- 级别：P1
- 状态：未修复

通俗解释：`spirit` 写的是“联系上级获取”，但卡片仍然做成了可点击下载按钮。

用户点击后只会打开当前导航页，并不会得到下载文件，也没有明确联系方式。

### BUG-008：语言切换按钮有一条样式没生效

- 级别：P2
- 状态：未修复

通俗解释：CSS 中少写了一个英文句点 `.`，导致语言切换按钮的默认样式可能不完整。

用户可能看到：按钮平时显示不一致，但鼠标移上去后又恢复正常。

### BUG-009：手机上不允许双指放大

- 级别：P2
- 状态：未修复

通俗解释：导航页主动关闭了浏览器缩放。

字体较小或视力不好的用户无法放大页面阅读。

### BUG-010：部分按钮只能用鼠标点

- 级别：P2
- 状态：未修复

通俗解释：“返回顶部、切换主题、切换语言”等功能外观像按钮，代码里却只是普通方块。

使用键盘、无障碍工具或部分特殊浏览器时，可能无法正常操作。

### BUG-011：网站没有站点地图

- 级别：P2
- 状态：未修复

通俗解释：以前的 `sitemap.xml` 已被删除，目前没有自动生成新的站点地图。

普通用户基本感觉不到，但百度、谷歌等搜索引擎可能更难完整收录网站页面。

### BUG-012：代码准备显示版本公告，但页面上没有放公告位置

- 级别：P2
- 状态：未修复

通俗解释：程序会寻找一个叫 `bulletin-content` 的区域，用来显示当前版本、更新时间和反馈邮箱，但网页里根本没有这个区域。

结果是：这段公告代码一直不生效。导航页现在显示版本信息的方式和代码原本设计的不一致。

### BUG-013：主题记录异常后，主题按钮可能点不动

- 级别：P2
- 状态：未修复

通俗解释：浏览器只应该保存“自动、浅色、深色”三种主题。如果保存成其他内容，网站不会自动纠正。

用户可能看到：点击主题切换按钮完全没有反应。清除网站 Cookie 后可能恢复。

### BUG-014：语言记录异常后，页面可能一半中文一半英文

- 级别：P2
- 状态：未修复

通俗解释：不同模块对异常语言值的处理方式不一样。

用户可能看到：按钮显示英文，但资源内容仍是中文，或者网页声明是英文，实际内容却是中文。

### BUG-015：版本文件读取失败时，网站什么都不提示

- 级别：P2
- 状态：未修复

通俗解释：如果版本文件丢失、地址错误或网络读取失败，代码会悄悄忽略错误。

用户仍会看到旧版本，却不知道数据没有更新；管理员也很难第一时间发现。

### BUG-016：部分导航内容直接拼进网页，没有先检查

- 级别：P2
- 状态：未修复

通俗解释：侧栏和部分卡片会把数据直接当成网页代码插入，没有统一检查标题和链接是否合法。

目前数据由自己维护，风险不算紧急；但以后如果接入接口、自动更新或导入外部数据，错误内容可能破坏页面，危险链接也可能被放进去。

### BUG-017：还有几个下载地址使用不安全的 `http://`

- 级别：P2
- 状态：未修复

通俗解释：网站本身是 HTTPS，但部分资源链接仍是旧的 HTTP 地址。

用户可能遇到：浏览器安全警告、链接被强制改成 HTTPS 后打不开，或者 QQ、微信内置浏览器阻止访问。

### BUG-018：每张图片都单独启动一套监听程序

- 级别：P3
- 状态：未修复

通俗解释：如果以后导航卡片大量使用图片，每张图片都会建立一个独立的加载监听器。

图片少时感觉不明显，图片多后会浪费浏览器资源，手机页面可能变慢。

### BUG-019：顶部时间刚打开时会空白约一秒

- 级别：P3
- 状态：未修复

通俗解释：时钟代码先等待一秒，之后才第一次填写时间。

用户刚打开页面时，会短暂看到空白时间区域。

### BUG-020：导航资料分散在多个补丁文件里

- 级别：P3
- 状态：未修复

通俗解释：仓库里的原始导航数据，不一定等于用户最终看到的内容。页面加载时还会经过多个补丁文件再次修改。

后果是：以后改一个资源时容易漏改、重复修改，或者中文改了但英文没改。

## 还不能直接确定的问题

下面这些不是已经确认发生的故障，需要实际构建和打开网页后才能下结论。

### RISK-001：正式构建后的资源路径可能不对

构建脚本会把网页文件移动到另一个目录，但没有明显看到同步修改网页里的相对路径。

需要实际执行构建，然后检查导航页的 CSS、JS、字体和图片有没有出现 404。这个风险很重要，但在没有实机构建结果前，不能直接说线上已经坏了。

### RISK-002：部分分类图标可能显示为空白

项目混用了不同版本的图标类名。需要逐个打开正式构建页面检查，才能确认哪些图标真的缺失。

### RISK-003：大量外部下载链接没有自动检查

当前测试只检查网站自己的页面，不会验证蓝奏、飞鸡盘、云盘和其他资源站是否还能打开。

因此某个外链失效时，自动测试不会提醒。

### RISK-004：Cloudflare 可能继续缓存旧网页

即使仓库已经更新，如果没有清理缓存，用户仍可能看到旧版本。

发布后应核对线上文件更新时间和内容，不能只看 GitHub 已提交就认为更新成功。

### RISK-005：第三方统计和外部图片可能拖慢页面

网站加载了百度统计、51.la、MySSL 图片和外部背景图。第三方服务变慢或被拦截时，页面可能报网络错误或加载变慢。

### RISK-006：HTTP 链接在不同手机浏览器中的表现不一致

网页要求尽量升级为 HTTPS，但数据里还有 HTTP 下载地址。

Chrome、QQ、微信和旧安卓浏览器的处理方式可能不同，需要分别测试。

## 自动检查还缺少什么

### QA-001：最新提交没有自动测试记录

看不到 GitHub Actions 的通过记录，所以不能只凭提交成功就认定页面正常。

### QA-002：普通测试不会自动检查页面外观

布局错位、文字重叠或按钮跑位，可能不会让普通测试失败。

### QA-003：现有截图测试主要按 Windows 保存

换到 Linux 服务器运行时，截图可能因字体和渲染差异无法直接比较。

### QA-004：主题切换缺少专门测试

没有自动检查白天、夜间、异常 Cookie 和跨时间切换，所以主题错误没有提前被发现。

### QA-005：导航数据缺少统一检查

目前没有在发布前自动检查：

- 是否出现空标题；
- 是否出现无效链接；
- 是否混入危险协议；
- 中文和英文分类是否对应；
- 当前版本日期是否已经过期。

## 建议处理顺序

本次按用户要求，只更新了 LOL 版本数据，其他代码保持不动。

以后需要继续修复时，建议按以下顺序：

1. 修复白天自动主题报错。
2. 实际构建一次，确认导航页资源路径是否正常。
3. 让损坏的语言或主题记录能够自动恢复。
4. 允许用户复制密码和提取码。
5. 处理没有真实下载地址的卡片。
6. 修复测试只能在 Windows 运行的问题。
7. 最后处理图标、时钟、站点地图和代码整理问题。

## 发布后最简单的人工检查

1. 打开首页和下载中心，确认没有错误提示。
2. 检查当前版本是否显示为 `26.15`。
3. 检查更新时间是否为 `2026年7月30日`。
4. 检查下次更新时间是否为 `2026年8月13日`。
5. 搜索任意资源，确认卡片能正常筛选。
6. 切换中文、英文、浅色、深色和自动模式。
7. 用手机打开，确认侧栏能展开和收起。
8. 打开开发者工具网络面板，确认站内文件没有 404。
