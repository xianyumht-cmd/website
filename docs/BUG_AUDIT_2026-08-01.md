## BUG-001：白天使用自动主题时，主题代码直接报错

- 严重程度：高
- 状态：未修复
- 文件：`src/assets/js/theme-mode.min.js`

### 固定触发条件

1. 浏览器时间处于 06:00—17:59。
2. 主题模式为“自动”。
3. 打开或刷新导航页。

### 固定结果

代码执行：

```js
document.body.classList.contains("")
```

浏览器不接受空的 class 名称，直接抛出异常。主题初始化在这一行中断，之后的主题文字更新不再执行；每分钟自动检查再次执行同一错误代码。

### 用户看到的结果

- 自动主题初始化报错。
- 主题状态和按钮文字不能按完整流程更新。

## BUG-002：语言 Cookie 含有错误百分号时，导航数据无法初始化

- 严重程度：高
- 状态：未修复
- 文件：`src/assets/app/resource-data.js`

### 固定触发条件

浏览器 Cookie 中存在以下内容之一：

```text
language=%
```

```text
site_language=%E0%A4%A
```

### 固定结果

代码直接执行 `decodeURIComponent()`，没有捕获 `URIError`。`initializeResourceData()` 在建立 `window.navData` 前终止。

### 用户看到的结果

导航资源卡片不生成，页面停留在加载状态或空内容状态。

## BUG-003：主题 Cookie 写入非法值后，主题按钮完全失效

- 严重程度：中
- 状态：未修复
- 文件：`src/assets/js/theme-mode.min.js`

### 固定触发条件

浏览器 Cookie 为：

```text
theme_mode=night
```

或任何不是 `auto`、`light`、`dark` 的值。

### 固定结果

1. 初始化代码把非法值直接保存到 `ThemeMode.current`。
2. `toggleMode()` 只处理 `auto`、`light`、`dark`。
3. 点击主题按钮时，`switch` 没有任何分支执行。

### 用户看到的结果

主题按钮点击后没有反应。清除或改正该 Cookie 后才能恢复。

## BUG-004：语言 Cookie 写入非法值后，第一次切换语言无变化

- 严重程度：中
- 状态：未修复
- 文件：
  - `src/assets/js/language-switcher.min.js`
  - `src/assets/app/resource-data.js`

### 固定触发条件

浏览器 Cookie 为：

```text
language=abc
```

### 固定结果

1. 语言按钮模块把当前语言记录为 `abc`。
2. 导航数据模块把内容回退到中文。
3. HTML 的 `lang` 属性被设置为英文。
4. 第一次点击语言按钮时，代码把 `abc` 改为 `zh`，页面内容仍然是中文。
5. 第二次点击后才切换为英文。

### 用户看到的结果

第一次点击语言切换按钮没有语言变化，需要点击两次才能进入英文。

## BUG-005：同一个导航页同时保存了 26.15 和 26.14 两套版本数据

- 严重程度：高
- 状态：未修复
- 文件：
  - `src/assets/data/lol-version.json`
  - `src/pages/nav/nav-patches.js`
  - `src/assets/js/nav-core.js`

### 当前实际数据

`lol-version.json`：

```text
26.15 / 2026-07-30 / 2026-08-13
```

`nav-patches.js`：

```text
26.14 / 2026-07-16 / 2026-07-30
```

### 固定执行结果

1. 页面先从 `nav-patches.js` 写入 26.14。
2. 页面随后读取 `lol-version.json`。
3. JSON 读取成功后，页面数据改为 26.15。
4. JSON 读取失败后，错误被空的 `catch` 忽略，页面继续保留 26.14。

### 实际问题

版本更新只改一处没有完成整个导航版本数据更新。两个文件必须保持一致，或删除其中一个版本数据源。

## BUG-006：当前版本号公告永远不会显示

- 严重程度：高
- 状态：未修复
- 文件：
  - `src/assets/js/nav-core.js`
  - `src/pages/nav/index.html`

### 固定原因

`nav-core.js` 只把版本公告写入：

```html
id="bulletin-content"
```

当前 `index.html` 中没有这个元素。

### 固定结果

下面四项公告渲染代码每次都被跳过：

- 当前游戏版本
- 本次更新时间
- 下次更新时间
- 失效反馈邮箱

### 用户看到的结果

更新 `lol-version.json` 后，导航页不会在原定公告区域显示版本号。页面只利用更新时间计算“几天前更新”。

## BUG-011：Playwright 测试在 Linux 和 macOS 上无法启动预览服务

- 严重程度：中
- 状态：未修复
- 文件：`playwright.config.ts`

### 固定原因

启动命令写死为 Windows 文件：

```text
node_modules\.bin\vite.cmd
```

Linux 和 macOS 中不存在 `vite.cmd`。

### 固定结果

在 Linux 或 macOS 执行 Playwright 测试时，预览服务启动失败，测试在打开网页前结束。

## BUG-012：性能测试在 Linux 和 macOS 默认找不到浏览器

- 严重程度：中
- 状态：未修复
- 文件：`scripts/perf-threshold.mjs`

### 固定原因

浏览器自动查找列表只有四个 Windows 路径：

- Windows Chrome 64 位路径
- Windows Chrome 32 位路径
- Windows Edge 64 位路径
- Windows Edge 32 位路径

### 固定结果

在 Linux 或 macOS 未手工设置 `CHROME_PATH` 时，脚本固定抛出：

```text
No Chromium-based browser found. Set CHROME_PATH.
```

性能测试立即结束。
